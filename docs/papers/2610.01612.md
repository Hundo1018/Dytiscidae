# arXiv 2610.01612v1 — ReCo: faithful technical extraction

Status key: **VERIFIED** = read in the paper text (section/table cited); **INFERRED** = my reading; **UNKNOWN** = the paper does not say.
Source read: full PDF text of arxiv.org/pdf/2610.01612v1 (via pdftotext), 2026-10-06. The paper is a short robotics-conference-style manuscript (no appendix, no supplementary parameter tables in the PDF). Figures were not inspected (text only).

**Scope warning (VERIFIED):** this paper is about *legged manipulation* (quadruped + arm), not quality-diversity, morphology search, flapping flight, or multi-fidelity evaluation. Everything in section 6 is an analogy drawn by me.

## 1. Citation

- Title: ReCo: Response-Consistent Locomotion with Policy-Aware MPC for Legged Manipulation
- Authors: Kuankuan Sima, Yichao Gao, Chenxi Gu, Kefan Zhao, Lin Zhao (National University of Singapore; ECE and ME departments)
- Submitted 1 Oct 2026 (cs.RO), arXiv:2610.01612v1. License CC BY 4.0 (abstract page).
- Code: none linked in the paper or abstract page (VERIFIED). Depends on OCS2 (open source), Walk These Ways interface, Isaac Gym (training), MuJoCo (evaluation).

## 2. Problem and setting

A quadruped with a 6-DoF arm (Unitree Go2 + X5 arm) must track a time-indexed world-frame end-effector SE(3) trajectory while walking. Hybrid architecture: a learned locomotion policy drives the legs; an MPC chooses *locomotion commands* (planar velocity, yaw rate, height, pitch) and *arm joint velocities* jointly. The authors' claim: MPC can only compensate for base motion it can predict, and a learned policy's command-to-motion response varies with gait phase, contact and payload (and with arm motion), so the planner's model of the policy is wrong. Their key insight (Sec. I): train the policy to be not only robust but *predictable by the planner that commands it* ("a consistent delay can be compensated by feedforward, a variable delay cannot"), then identify a low-order closed-loop response model of the frozen policy and put it inside the MPC.

## 3. Method

Three parts: (A) response-consistent policy training, (B) offline identification of a closed-loop response model of the frozen policy, (C) MPC that plans over that model plus arm kinematics.

### 3.0 Interfaces (VERIFIED, Sec. III-A)
- Policy: gait-conditioned (Walk These Ways interface, Margolis & Agrawal 2023), proprioception + commands + gait timing. Command c = (cx, cy, cω, ch, cθ) in R^5 (planar velocity, yaw rate, height, pitch). Gait setting is fixed over each prediction horizon. No roll command.
- Base prediction state x_base = (p_W in R^3, ψ, θ, ρ, vx, vy, ωz) in R^9 (ZYX yaw/pitch/roll; heading-frame velocities; body-frame yaw rate).
- Full MPC state x = (x_base, φ, q) in R^16 (φ = gait phase, q = 6 arm joints); input u = (c, u_q) in R^11 (u_q = 6 arm joint velocity commands); arm kinematics q̇ = u_q.

### 3.1 Response-consistent training (Sec. III-B, Table I)
PPO, Walk-These-Ways gait interface. "Response shaping" = four extra terms added to the normal locomotion reward/regularisation. They act on y = (vx, vy, ωz, h, θ) where h = body height relative to nominal.

1. Critically damped reference generator per channel i (Eq. 3):
   ξ̈_i = λ_i²(c_i − ξ_i) − 2 λ_i ξ̇_i, with |ξ̇_i| ≤ r_i. Unsaturated: exact zero-order-hold discretisation; saturated: rate-limited ramp. c_h uses the same nominal offset as h. λ_i (bandwidth) and r_i (rate limit) per channel: **UNKNOWN values**.
2. Gait-periodic estimate: ỹ = y − δ̂(φ, ν), ν = planar speed. δ̂ = running means over (phase, speed) bins, updated every env step, **from nominal-domain environments only**. Bin counts / averaging constants: UNKNOWN.
3. Reference-tracking reward (Eq. 4): r_ref = g · Σ_i w_i exp(−(ỹ_i − ξ_i)²/σ_i²) / Σ_i w_i. Gate g ∈ {0,1} is 0 during external disturbances and a post-disturbance interval. w_i, σ_i: UNKNOWN. Contributes to r+.
4. Phase repeatability loss: ℓ_phase = Σ_i μ_i^ph w_i^ph (y_i − ȳ_i − δ̂_i)², ȳ = low-pass local mean. Penalises deviation from the *repeatable waveform*, not amplitude. Channel mask μ activates after settling. Enters r−.
5. Steady-state gain loss: ℓ_gain = Σ_i μ_i^ss w_i^ss (ỹ_i − c_i)². Discourages settled command bias. Enters r−.
6. Cross-domain consistency (Eq. 5): environments are grouped; each group shares identical command sequences and gait phases and contains one nominal env plus instances with randomised mass, payload, friction, actuator strength. Instance d incurs ℓ_domain^d = m^d ‖ỹ^d − ỹ^nom‖²_W, W weighting all five channels (including height). Mask m^d excludes nominal, invalid, or desynchronised comparisons. Group size, randomisation ranges, W: UNKNOWN. Enters r−.

Combination: r = r+ · exp(c− · r−), c− > 0 (the Walk-These-Ways multiplicative form); r+ ≥ 0 includes r_ref, r− ≤ 0 holds the three losses. Curriculum (VERIFIED, order only): locomotion first -> reference tracking -> consistency penalties -> broader randomisation -> stronger disturbances. Stage lengths: UNKNOWN.
Compute: converges in ~10 h on one RTX 4090, ~12 GB GPU memory (Sec. IV-A). Network sizes, observation/action dims, PPO hyperparameters, env count, control rate: **UNKNOWN (not in the paper)**.

### 3.2 Closed-loop response model (Sec. III-C, Eqs. 6-8)
Fitted to the *frozen* policy; low-order, hand-structured, per channel.
- Planar velocity (i in {x,y,ω}, vω = ωz): v̇_i = (k_i c_i − v_i)/τ_i (first-order lag, gain k_i, time constant τ_i). The 2nd-order training reference (Eq. 3) is a *target*, not the assumed closed-loop order.
- Height/pitch/roll, η = (z, θ, ρ) where z = world height of the base frame at the arm mounting plane (Eq. 7):
  δ_j = Σ_{n=1..N_h} (a0_jn + a1_jn ν) sin(nφ + β_jn); η̇_j = [b_j + k_j c_j − (η_j − δ_j)]/τ_j + δ̇_j; φ̇ = 2π f_g.
  N_h = 2 (stride and half-stride). c_z = c_h; roll has k_ρ = 0. Only b_z is nonzero (mounting-plane height at c_h = 0). ν = sqrt(vx²+vy²+ε), small ε>0. The lag acts on η − δ; δ̇ handles phase/speed variation. δ is identified offline, separately from the training-time δ̂.
- Yaw kinematics (Eq. 8): ψ̇ = (ωz + sin ρ · θ̇)/(cos θ cos ρ). Planar world velocity = yaw-rotated (vx, vy).
- No explicit arm-induced-wrench model; the shaped policy is meant to make that unnecessary.
- Identification: bounded nonlinear least squares on multi-step open-loop prediction errors; step, ramp, chirp commands across randomised domains; identification data disjoint from the evaluation runs. One model fitted per frozen policy. Optimiser, bounds, data volume, fitted k/τ values: UNKNOWN.

### 3.3 Policy-aware MPC (Sec. III-D, Eqs. 9-11)
- Dynamics ẋ = f(x,u) = response model + arm kinematics; EE pose T_WE = T_WB · T_BE(q) (includes arm mounting transform).
- OCP (Eq. 9): min Φ(x(t+H)) + ∫ [ℓ(x,u) + P(x,u)] dt, s.t. ẋ=f, x(t)=x̂(t). P = soft penalties on joint bounds, command bounds, selected self-collision distances.
- Stage cost (Eq. 10): ½‖e_p‖²_Qp + ½‖e_R‖²_QR + ½‖ṗ_WE − ṗ_WE^ref‖²_Qv + ½‖u‖²_Ru + ℓ_base (pitch, roll, yaw-rate, command-vs-response discrepancy) + ℓ_posture (arm deviation from a compact nominal pose). Orientation residual (Eq. 11): e_R = w·v_r − w_r·v + v×v_r (unit quaternions, reference sign-aligned when w_r w + v_r·v < 0). Terminal Φ penalises EE pose error. Q/R weights: UNKNOWN. Reference: positions linearly interpolated, orientations by quaternion interpolation, velocities from interpolated slopes.
- Solver: OCS2 multiple-shooting SQP with autodiff; warm-started; 100 Hz; H = 1.0 s; 67 shooting nodes (~15 ms); 3 SQP iterations per update; RK2; 3 threads. Reference manager samples faster than the update rate and holds commands between updates. Latency compensation: measured state propagated over one sampling interval. Feedback = base state (simulator in sim; leg-kinematics odometry on hardware), arm joint positions, gait phase from the policy clock; phase wrapped to [0,2π) in shooting constraints.

### What is learned vs fixed
Learned: the RL locomotion policy (PPO, shaped reward). Fitted offline (least squares): response-model parameters (k, τ, b, a0, a1, β per channel). Fixed/hand-designed: model structure (1st-order lags, N_h=2 harmonics), reference generator, MPC cost weights and solver settings. Nothing is learned online.

## 4. Experiments

### Setup (VERIFIED, Sec. IV-A)
Go2 + X5 in MuJoCo, 2.5 ms step; deterministic 16x16 m rolling heightfield, elevation in [-0.10, 0.10] m, RMS 0.0438 m. 50 world-frame EE pose trajectories from random sketched paths (targets may be outside arm workspace at a fixed base pose, so locomotion is required). Each controller runs each trajectory nominally and with an 80 N world +X force at base CoM for 0.1 s (8 N·s) -> 100 runs/controller. Learned controllers trained in Isaac Gym, evaluated in MuJoCo (sim-to-sim). Success: >=97% final progress, no fall/numerical fault/early termination; endpoint error <=0.15 m and <=40 deg held >=0.5 s; >=40% of samples within both tolerances. RMSE of early failures covers only the recorded prefix (so must be read with falls/progress). Stats: mean ± sample std of per-run RMSE; paired Wilcoxon signed-rank, Holm-corrected, p<1e-3 vs every baseline on both metrics. **Training seeds: UNKNOWN / apparently one trained policy per method** (variance is across trajectories/conditions, not across training runs). Baselines retrained "from public implementations... matching our training budget" (budget not quantified); Ma et al. reimplemented on the same OCS2 infrastructure; RoboDuet and Visual WBC need external base velocities so are paired with a pure-pursuit tracker; UMI-on-Legs retrained on Go2-X5 (in-distribution RMSE 0.035 m / 4.7 deg, but falls in 80/100 on the benchmark).

In closed loop adding the component: position RMSE -5.5%, orientation -6.9%, vertical tracking error in the 1.5-8 Hz band -6.5%. (Closed-loop gain is far smaller than the open-loop prediction gain.)

## 5. Limitations

Stated by the authors (VERIFIED):
- Identification improves position but worsens orientation (attributed to omitted translation-rotation coupling in per-channel model); future work: coupled arm-base dynamics.
- Height response is not made more repeatable by shaping despite being in the cross-domain loss; future: shape the height response.
- Disturbance test covers a single direction, duration and schedule; baseline comparison "does not isolate planning from differences in the underlying controllers"; baselines needing external base commands are paired with a simple pure-pursuit tracker.
- Hardware EE metrics are in the estimated frame; no ground truth for odometry drift outside mocap.
- Perceptive locomotion is future work (benchmark terrain is mild: RMS 0.044 m).

INFERRED:
- Single training run per method; no variation across policy seeds, so success counts (75 vs 42) could partly reflect training luck. Baselines retrained at "matching budget", not tuned per-method; strongest baselines are adapted, not native, to the task.
- Success counts depend on author-defined thresholds (0.15 m, 40 deg, 97%, 40% in-tolerance).
- The response model is fitted *after* training to a frozen policy; no feedback from model mismatch into training (and shaping is a bundle, so which term matters is unknown).
- Full-method hyperparameters (weights, sigmas, lambdas, ranges, network, PPO settings) are absent; reimplementation requires guessing.
- Closed-loop benefit of the periodic component is modest (5-7%) relative to its open-loop prediction gain.
- Sim-to-sim evaluation (Isaac Gym -> MuJoCo) with mild terrain; the sim benchmark is the paper's own.

## 6. Touchpoints (SPECULATIVE — the paper never touches QD, morphology search or flight)

The transferable idea: *make a learned component's input-to-output response low-variance and low-order-predictable across a perturbation set (via a consistency term against a nominal instance), then fit a small parametric model of it and let a planner/optimiser use that model instead of assuming ideal execution.* Mapping to Dytiscidae:

1. **Shared PPO policy as variation operator / controller across morphologies.** Add a cross-instance consistency penalty (identical command sequence on nominal body and randomised-parameter bodies; Eq. 5 analogue) so the controller's response to its gait/command parameters is body-invariant. Precondition: a well-defined command vector and a measurable response vector y (e.g. thrust, speed, pitch response) that exists in every body, and a nominal reference body; also precondition that policy-gradient steps are actually applied (the project notes it was previously never scored).
2. **Gait-periodic response model (Eq. 7 analogue) for flapping.** Fit a phase-conditioned harmonic series (N_h=2) of body height/pitch/thrust vs flap phase and speed, so the within-stroke oscillation is separated from the mean command response. Precondition: a flap-phase signal and enough per-design rollout data; the quasi-steady solver must show cycle-periodic behaviour (the paper's own gain from this component was small, 5-7% closed loop).
3. **Cheap per-medium response model as an MPC/learned-critic surrogate.** The "Tier-1 command response" could be summarised by a few (k, τ) per channel, fitted by bounded least squares on step/ramp/chirp commands, giving a low-dimensional descriptor of how well a design realises a command. Precondition: identification rollouts add cost (Tier-1 evals already ~110-225 s/gen); worth it only if the fitted (k, τ, residual) predict Tier-2 mission residuals better than the current critic features. Pure hypothesis.
4. **Repeatability/"predictability" as a descriptor or quality term.** Phase-conditioned residual RMS (Table IV style) as a behaviour descriptor or tie-breaker for MAP-Elites cells, favouring designs a planner can control. Precondition: it must be gated against the passive-motion leak (a still or tumbling machine can be perfectly "repeatable", the failure class in the project's measurement rules); would need the still-machine check before use.
5. **Steady-state-gain / command-bias term (Eq. like ℓ_gain) as a gate** against designs that move without being commanded: |ỹ − c| after settling directly encodes "tell the machine what to do". Precondition: commanded two-phase segments already exist; this reads as a refinement of the existing gate, not a new mechanism.
6. **Not applicable (INFERRED):** the OCS2 MPC and arm/EE-tracking parts have no counterpart; the paper offers nothing on sparse reward, QD archives, infeasibility with part count, or multi-fidelity critics. Its evidence is also weak for transfer: one policy per method, sim-to-sim, mild terrain, and no per-term ablation of the shaping bundle.
