## 3. Data-handling decisions, each forced by something in the files

1. **Resumed runs (surviving timeline).** `a8_segments.py` splits `generations.jsonl` at each
   `run_start` line and `events.jsonl` where `t` (seconds since that process's telemetry was
   created, `ops/telemetry.py:59,72`) drops; a segment keeps generation g iff g is below the first
   generation of every later segment. Runs affected: arch46 (an empty first process), arch53
   (gens 161-170 re-run, 118 evaluations discarded), arch57 (1-13, 148), arch58 (221-224, 47),
   arch59 (121-139, 225), arch60 (seven processes; 41-55 and 101-112 re-run, 320 discarded). All
   counts below are on the kept timeline; discarded work appears only in T1.
2. **Seeds are one evaluation filed on every island** (`evolution/loop.py:3004-3009`), so gen-0
   `evaluate` events are 7-8 copies of one rollout. Every physical count de-duplicates `operators
   == ["seed"]` on (eval_seed, body_plan, mass); island series (T5) keep every filing. Identity
   check: `evaluated` on the last kept generation line equals evaluate (non-seed) + tier0 (non-seed)
   + reevaluate + physical seeds + a residual of 0-10, which equals the `exploits.jsonl` line count
   in 13 of 18 runs and differs by at most 3 in the rest (T1).
3. **`archive.json` is not the final archive.** It is the visited island's dashboard export every
   5 generations (`ops/run.py:321-323`); it matched `archive_generalist.json` in arch45/48/49/51,
   `archive_land_air.json` in arch46, `archive_amphibian.json` in arch47 and `archive_air.json` in
   arch50. T3/T7/T8 read `archive_<island>.json`, the export at the last checkpoint or at the end
   of `run_search` (`evolution/loop.py:2470-2473, 2512-2515`). For runs killed between checkpoints
   that export is older than the last generation: arch43 gen 20 (ran to 39), arch50 gen 120 (121),
   arch52 gen 80 (99), arch60 gen 100 (112). For the two single-island ones the newer
   `archive.json` (gen 95, gen 110) is summarised as a check row in T3c; it changes no conclusion.
4. **Notes were cut at three before `eb9b79d`.** The evaluate event kept `result.notes[:3]` until
   2026-10-08 ("the evaluate event keeps eight notes, not three (land_to_air was cut)"), first in
   arch50's commit; arch43-49 are read with a cap of 3. The crossing count therefore comes from
   `ladder_measurements.transition.crossed_fraction` x 4 (`envs/transitions.py:805`, written at
   `evolution/loop.py:1360`), and notes only attribute it to a kind. Every one of the 89,464
   evaluations resolved: either the note-less kinds number exactly the crossings, or the list was
   cut and nothing crossed (`not_crossed_note_cut`: the cut kind is known not crossed, its failure
   class is unknown). No uncut record disagreed.
5. **The hold precondition is recorded only for machines that reached the target medium.**
   `did not hold before the command to cross` is set iff `cross >= 0 and hold < HOLD_PASS` (0.5,
   `envs/transitions.py:256, 493-498`); `never crossed the boundary` says nothing about the hold;
   an aborted probe has its hold set to 0 (`transitions.py:470`). The per-kind hold value is not
   serialised. T2d therefore gives bounds, not a share. The only other trace is the mean graded
   approach `ladder_measurements.transition.crossed`, which for air and land targets is
   0.6 x progress x hold: it is > 0 on 39.5-62.2% of X1 evaluations with no crossing (T2c last
   column), which shows a nonzero hold somewhere on those bodies, not a hold >= 0.5.
6. **Three different "missions".** Tier-1 `mission_fraction` (`envs/evaluate.py:217-223`) is
   sqrt(min c) x mean c x energy x max(transition, 0.05) x max(take-off, 0.05): it is > 0 whenever
   all three competences are > 0, rounded to 4 dp in the record. Tier-2 `tier2_fraction`
   (`promote` events; `envs/evaluate.py:575-639`) is legs passed / legs, each leg 25 s simulated
   (300 s / `time_compression` 12) and re-placed in its medium, passed iff competence >= 0.15
   (`LEG_COMPETENCE_BAR`, `evaluate.py:442`) and survived, stopping at the first failure; it has no
   crossings. The film manifest's `mission.transitions` is the continuous mission from the beach,
   one design per run. All three are in T2a.
7. **Rounding.** Competences are stored to 3 dp (`evolution/loop.py:1252-1254`), so ">= 0.012"
   means a stored value >= 0.012 and "> 0" means >= 0.0005 unrounded.
